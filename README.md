# Контрпики Dota 2

Статический сайт: выбираешь героев врага, отмечаешь их позиции — получаешь список героев,
которые против них играют лучше обычного, с разбором «против кого сколько» и с разбивкой
по позициям (керри / мид / оффлейн / саппорты).

Сервера нет, API в рантайме не дёргается, ключи не нужны. Два файла — `index.html` и
`data.js` — работают даже двойным кликом с диска.

## Как запустить

Просто открыть `index.html` в браузере (двойной клик). Всё.

Иконки героев тянутся с CDN Valve, поэтому нужен интернет. Если нужен полный офлайн —
скачай 127 png в папку `img/` и поменяй `CDN` в `index.html`.

## Как выложить бесплатно

Любой из вариантов, все бесплатны и без карты:

- **GitHub Pages** — создать публичный репозиторий, залить `index.html` и `data.js`,
  Settings → Pages → Deploy from branch → `main` / `/ (root)`.
  Через минуту сайт живёт на `https://<логин>.github.io/<репозиторий>/`.
  Готовый скрипт для этого — `publish.ps1` (см. ниже).
- **Cloudflare Pages** — drag&drop папки, получаешь `*.pages.dev`, репозиторий может быть
  приватным.
- **Netlify Drop** — `app.netlify.com/drop`, перетащить папку, ссылка сразу.

Важно: `index.html` должен лежать в корне, `data.js` рядом с ним.

### Если через GitHub Pages

```powershell
cd dota-counter
.\publish.ps1 -User твой_логин
```

Сначала создай на github.com **пустой** репозиторий (без README), потом запусти скрипт:
он сделает коммит, добавит remote, запушит и откроет браузер для входа. Скрипт
переключает git на OpenSSL-бэкенд — на этой машине стандартный schannel не работает
из-за заблокированного хранилища сертификатов.

## Что внутри

| файл | зачем |
|---|---|
| `index.html` | сам сайт (интерфейс + скоринг), без зависимостей |
| `data.js` | готовая матрица: 127×127, винрейты пар и «чистый» контр-эффект |
| `build_data.py` | пересборка `data.js` из OpenDota (Python 3, без библиотек) |
| `validate_model.py` | проверка, насколько сигнал вообще воспроизводится |
| `check_model.py`, `smoke.js` | быстрый просмотр выдачи без браузера |

## Как считается

1. Один SQL-запрос к OpenDota explorer отдаёт по всем парам героев число игр и побед.
2. Складываем обе стороны пары — так убирается преимущество Radiant.
3. Винрейт пары сглаживается к базовому винрейту героя (Байес, `K = 250` игр):
   иначе редкие пары дают экстремумы из шума.
4. Двухфакторная модель в логитах: `x(a,b) ≈ θa − θb + μ(a,b)`.
   `θ` — насколько герой силён вообще, `μ` — насколько он хорош **именно** против
   этого героя сверх своей обычной силы. Сайт ранжирует по `Σμ` и показывает `μ × 25`
   как «процентные пункты».

## Позиции 1–5

В API позиций нет — там только грубые роли (Carry/Support/Nuker), которые не отличают
керри от мидера. Поэтому позиции выводятся из данных, вторым SQL-запросом:

- берутся `lane_role` (1 — безопасная, 2 — мид, 3 — сложная) и `net_worth`;
- мид = позиция 2;
- в безопасной линии кто богаче — позиция 1, второй — 5;
- в сложной линии кто богаче — позиция 3, второй — 4.

Проверка на реальных героях: Anti-Mage → P1 87%, Invoker → P2 92%, Axe → P3 85%,
Crystal Maiden → P5 85%, Lifestealer → P1 92%. Pudge ожидаемо размазан по всем пяти.

Как это используется:

- **Позиция врага** ставится автоматически (самая частая) и меняется кликом по номеру
  на портрете. Влияет на вес: контрить керри и мидера важнее, чем саппортов
  (коэффициенты 1.15 / 1.15 / 1.0 / 0.9 / 0.9).
- **Своя позиция** фильтрует и сетку, и выдачу: показываются только герои, для которых
  эта позиция одна из двух основных. Иначе Pudge и Nature's Prophet висели бы во всех
  пяти списках сразу.
- Без выбранной позиции выдача разбита на пять блоков по три кандидата.

## Честно про качество данных

Это главное, что стоит знать перед использованием.

- OpenDota держит в открытой базе **~253 тыс. матчей** (2.5 млн строк `player_matches`).
  Из них получается 6.3 млн парных наблюдений, медиана ~680 игр на пару, ~340 в одну
  сторону. Больше бесплатно оттуда не достать — это их сэмпл, а не весь датасет.
- Сэмпл смещён: в нём перепредставлен высокий MMR, поэтому зоо-герои (Chen, Lycan,
  Beastmaster) выглядят сильнее, чем в среднем по пабам. Поэтому ранжирование идёт по
  «чистому контру», а не по абсолютному винрейту — иначе в топе всегда были бы они.
- `validate_model.py` делит матчи на две случайные половины и смотрит, повторяется ли
  эффект. На самых отыгранных парах корреляция **~0.30**: примерно треть дисперсии —
  сигнал, остальное шум. Для пар с малой выборкой верить почти нечему.
- Данные покрывают все патчи сразу, без фильтра по версии. Свежий патч может поменять
  картину, а данные этого не заметят.

Вывод: сайт — **ориентир, а не оракул**. Он хорошо отвечает на «кем в принципе
неплохо закрыть этих пятерых» и плохо — на «дай точный ответ с точностью до героя».
Строка «надёжно / средне / мало данных» под каждым кандидатом показывает, насколько
ему можно верить.

## Как сделать точнее

Единственный реальный апгрейд — данные лучше. Бесплатный токен STRATZ (регистрация на
stratz.com, 2 минуты) даёт доступ к агрегатам по десяткам миллионов матчей с фильтром
по патчу и брекету. Тогда в `build_data.py` меняется источник, а `data.js` и сайт
остаются те же — формат матрицы не изменится.

## Обновить данные

```bash
python build_data.py     # ~10 секунд, перезапишет data.js
```

Нужен только Python 3. Скрипт сам ходит в OpenDota, считает модель и пишет `data.js`.
